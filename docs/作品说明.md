# 智训引擎作品说明

官方 SDK 1.0.2 接入版本

## 一 方案与任务

队伍 WillWangzihuan，负责人王子欢。版本日期为 2026 年 11 月 17 日。本方案使用基础模型 Qwen/Qwen3.8-27B 生成工业模型续训程序，并根据平台测量结果选择产物。大语言模型未进行参数微调，不使用持久化 Sampler 微调权重；被续训和评分的是平台提供的工业模型。

工业模型需要随轮次数据更新。单次代码运行成功，不能证明优化器连续性、附加模型继承和预测入口一致。本版将这三项要求接入官方 contest_harness 1.0.2，使训练、候选测量、选择、状态保存和预测通过同一轮次协议交接。

| 任务 | 输出与单位 | 主要评价方向 |
|---|---|---|
| A 气体识别 | 6 类气体分类 | Macro-F1 越高越好 |
| B 轴承健康 | 剩余寿命，分钟 | RMSE、MAE 越低越好 |
| C 发动机寿命 | 剩余寿命，循环 | RMSE 越低越好 |

## 工程实现与证据

1. 将原来的 workspace_io 接口迁移至官方 SDK，统一 describe、train、predict 三个入口。实际历史、父产物、调用 ID 和结束确认均由 SDK 提供；A/B/C 各连续 10 轮的本地流程验证支持这一接口实现。

2. 候选保存完整工业模型，而非仅保存核心网络。Adam 状态、标准化参数、A 的附加分类头和读出表达式、C 的残差树均可恢复。独立预测进程及附加能力的 4 轮测试核对了这一行为。

3. 将程序故障与产物选择分开记录。错误明确标注发生阶段，失败不转换为固定规则训练或假报成功；8 类故障测试核对了退出状态和失败位置。

以上是本版可验证的工程贡献，不主张新的学习理论或已证实的性能优势。任务目标与比赛的 CPU 工业模型连续优化一致，实际比赛效果仍以平台完整运行与隐藏测试为准。

## 二 逐轮运行与模型更新

1. 读取平台 start 帧、当前任务公开训练和验证数据、实际父检查点。核对父文件摘要及任务类型，恢复完整模型；训练集和验证集的样本 ID 不允许重叠。

2. 通过 rnd.history 读取历史，复制上轮原生状态到工作区。第一次 rnd.model 调用接收真实父模型、历史和公开数据诊断，提出一次数值续训实验。平台负责绑定基础模型、附加官方提示和计量调用。

3. 校验提案中的计划、学习率、样本权重、批次顺序、损失及梯度函数。数值程序受语法与操作范围约束；有限差分检查校验梯度。训练从已有优化器状态继续，验证标签不参与拟合或梯度计算。

4. 保存完整候选，通过 rnd.submit_candidate 声明 checkpoint.npz 与预测命令。平台测量后，第二次 rnd.model 接收原始测量回执，选择当前候选或父产物并说明理由。没有本地固定阈值替代模型选择。

5. 保存实际调用 ID、历史 ID、提案、候选回执和选择理由。rnd.finish 提交选中产物，并等待 round_ack。下一轮只使用平台实际提供的父产物，不假定最近候选已被采用。

| 位置 | 用途 |
|---|---|
| /app、/data、/previous | 只读代码、公开数据、实际父产物 |
| /state、/model | 只读历史状态、预测时选中产物 |
| /workspace、/tmp | 本轮输出与临时文件 |

## 执行与预测约束

CPU 更新子进程沿用 20 秒 CPU 限制与 40 秒等待上限；本程序的训练计划为 1 至 5 个 epoch，累计更新不超过 1,500 步。这些是本版执行器约束，平台实际任务资源仍由宿主控制。

预测读取 CONTEST_ARTIFACT_PATH 指定的完整检查点。每收到一行 task/inputs 样本，立即输出并刷新一行 outputs，再读下一行。默认镜像命令仅 describe；训练须显式调用 python3 /app/harness.py train。

## 三 本地验证与结果分析

验证使用真实公开数据、实际 CPU 续训、文件保存与重新加载、独立逐行预测进程和原版 SDK。macOS 测试宿主仅映射平台挂载路径。训练提案采用历史千问文本回放；选择分支和附加能力使用明确标注的测试回答。它们不是本次新生成的模型回答。

| 检查 | 数量 | 观测结果 |
|---|---|---|
| 官方 SDK 回归测试 | 15 项 | 通过 |
| 连续轮次 | A/B/C 各 10 轮 | 30 轮完成并确认 |
| 独立预测响应 | 259,720 次 | 与完整模型直接预测一致 |
| 保留父模型分支 | 6 次 | 下一轮仍继承选中父产物 |
| 附加模型验证 | A/C 各 2 轮 | 另核对 48,586 次预测 |
| 故障路径 | 8 类 | 非零退出，阶段匹配 |

连续轮次验证回答的是“训练、提交、选择和下一轮继承能否形成完整流程”。每轮均有优化器实际更新；保留父模型的测试分支说明程序没有把被拒绝的候选偷偷带入下一轮。预测响应数包含同一公开验证集的重复调用，不是不同样本数量。

附加模型验证回答的是“核心更新会不会丢失完整状态”。A 的已拟合分类头各数组与读出表达式保持不变；C 的树数由 3 增至 6，原有前三棵树保持一致。结果支持这两条保存与继承路径，不等于提升了泛化性能。

8 类故障为：父模型摘要不符、任务不符、非法 JSON、非法程序、模型回答截断、选择未声明产物、重复调用 ID、平台拒绝结束确认。各项均核对了错误阶段、已发生的调用次数和是否已提交候选。

## 结论的适用范围

这里没有进行新旧模型效果的受控对照，也没有新的真实千问决策重复实验、隐藏阶段测试或统计置信区间。因此不能据此推断模型优化收益、真实网关成功率或鲁棒性。macOS 与镜像中的 Python/NumPy 版本不同，静态镜像检查不能替代 Linux 容器运行。

本地回放中的决定和相同公开数据属于测试条件，不能作为比赛所要求的真实自主优化记录。历史 SwanLab 记录和本版离线验收分别标记；后续平台结果须独立追加。
